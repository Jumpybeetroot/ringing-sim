# The Physics of the Ringing Simulator

The Kalico Ringing Simulator is designed to accurately visualize how input shapers and mechanical resonance interact in 3D printers. However, naively comparing the physical location of the print head to the target coordinate at a given timestamp produces massively inaccurate visualizations due to tracking lag. 

This document explains the mathematics we use to eliminate **Temporal Lag** and exclusively measure **Spatial Deviation** (the actual aesthetic defect on the print).

## 1. The Mass-Spring-Damper Model
The simulator models the 3D printer toolhead as a 2D mass attached to the commanded coordinate via a damped spring (the belts/frame).

The differential equation driving the physics engine is:
```text
x''(t) + 2*zeta*w_n * x'(t) + w_n^2 * x(t) = w_n^2 * x_cmd(t)
```
Where:
* `w_n = 2 * PI * mech_freq` (Natural angular frequency)
* `zeta = mech_damping` (Damping ratio)
* `x_cmd(t)` is the target position generated by the kinematic engine (potentially altered by an input shaper).

## 2. Temporal Tracking Lag (Why straight lines turn red)
If the toolhead is moving down a straight line at a constant velocity `v`, both the input shaper and the physical mass-spring system naturally induce a constant time delay (lag).

### A. Input Shaper Group Delay
An input shaper works by splitting the motor command into multiple delayed impulses to cancel out the resonant frequency. Because the impulses are delayed, the actual command trails behind the original target.
The group delay `T_s` is the center-of-mass of the impulses:
```text
T_s = sum(A_i * t_i) 
```

### B. Viscous Damping Lag
Even if you turn the input shaper off (`T_s = 0`), the physical toolhead still drags behind the commanded coordinate due to friction/damping in the mechanical system. Solving the differential equation for a steady-state constant velocity reveals a constant time lag `T_m`:
```text
T_m = 2 * zeta / w_n
```

### The Problem
If the toolhead is moving at `300 mm/s` with a total lag of `0.01 seconds`, the physical toolhead is trailing `3.0 mm` behind the target coordinate. 

If we calculate the error simply as the Euclidean distance (`sqrt(dx^2 + dy^2)`) between the toolhead and the reference target at time `t`, the simulator registers a catastrophic `3.0 mm` error, completely coloring the straight line **Red**. 
But in a real 3D print, dragging 10 milliseconds behind on a straight line doesn't matter as long as the plastic is laid down exactly on the geometric line. 

## 3. Isolating Spatial Deviation (The Fix)
To make the heatmap accurately reflect real-world print defects (wobbling off the line and cutting corners), we must mathematically eliminate all lag along the tangent of the path.

### Step 1: Aligning the Geometries
First, we shift the reference target backward in time by the exact total tracking delay:
```javascript
Total Delay = T_s + T_m
Ideal Index = Math.max(0, current_step - Total_Delay / dt)
```
This guarantees that during constant velocity, the reference target perfectly overlaps the physical toolhead.

### Step 2: Perpendicular Vector Projection
During acceleration and cornering, velocity changes rapidly, causing the tracking lag to fluctuate wildly. Time-shifting alone cannot account for this transient lag.

To definitively solve this, the physics engine passes the true geometric **Tangent Vector** (`dir_x, dir_y`) of the ideal line into the graphics renderer. 

We then calculate the raw error vector `V` between the actual toolhead and the ideal reference target. 
We find the "Tangential Error" by taking the dot product of `V` and the Tangent Vector:
```javascript
Tangential_Error = V.x * dir_x + V.y * dir_y
```
Finally, we use the Pythagorean theorem to perfectly subtract the Tangential Error from the Total Error, leaving *only* the **Perpendicular Deviation**:
```javascript
Total_Error_Sq = V.x^2 + V.y^2
Perpendicular_Error = sqrt(Total_Error_Sq - Tangential_Error^2)
```

## Conclusion
Because the Kalico Ringing Simulator calculates error via Tangent Vector Projection, it is completely immune to temporal tracking lag, acceleration lag, and shaper group delay. 

The color heatmap **strictly represents structural geometric deviation**:
1. **Mechanical Ringing** (The toolhead vibrating perpendicular to the wall).
2. **Shaper Smoothing** (The toolhead physically cutting the corner because the tangent vector instantly changes at a 90-degree intersection).
